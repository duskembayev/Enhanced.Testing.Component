# Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| `DockerUnavailableException` or "Docker is either not running or misconfigured" | Docker isn't running or isn't reachable | Start Docker. Only container harnesses need it. |
| `CS0122: 'Program' is inaccessible due to its protection level` | Top-level `Program` is internal (before .NET 10) | Add `public partial class Program;` to `Program.cs` or `InternalsVisibleTo` for the test project. |
| `CS0436: The type '...' conflicts with the imported type` for gRPC messages | The `.proto` is generated in both the service and the test project, which references the service | Generate client and server in the service (`GrpcServices="Both"`) and remove the `Protobuf` item from the tests. |
| `InvalidOperationException: Component not started.` | A harness was used before the component started it, after the component stopped it, or it was never added with `AddHarness` | Add the harness with `AddHarness`, and use it only between the fixture's start and dispose. |
| `InvalidOperationException: The component has not been started.` | A harness called the component (`CreateClient`, `Services`) from its own start, before the app started | Call the app from tests, not from a harness's start; an HTTP or gRPC client harness can only be used after `StartAsync` returns. |
| `InvalidOperationException: The component has been stopped.` | The component was used after `StopAsync`, or a harness touched it while stopping | Don't use the component or its harnesses after the fixture is disposed. |
| `InvalidOperationException: The component can be started only once.` | `StartAsync` was called twice | Build a new component instead of restarting one. |
| `NotSupportedException: The harness is already started by a component.` | One harness instance was added to two running components | Create a separate harness instance per component. |
| A harness can't connect to its container during start | It was added before the harness it depends on | Reorder: add it after its dependency. A dependent *container* needs `StartConcurrently = false`. |
| The app can't find its connection string / uses `localhost` defaults | `ConnectionName`/`ConfigurationKey` doesn't match the key the app reads | Use the exact configuration key (`ConnectionStrings:{ConnectionName}` for containers). |
| `InvalidOperationException: Failed to create Kafka topic '...'` | Invalid topic name or broker error (inner `KafkaException`) | Use letters, digits, `.`, `_`, `-` only. |
| `TimeoutException` from `WaitForKeyAsync`/`WaitForMessageAsync` | The message never arrived, went to another topic, or landed in a partition other than 0 | Check the topic name the app uses and that it produces to a single-partition topic; the message reports how many messages were skipped. |
| From some test on, every test fails with `InvalidOperationException: The application stopped while the component was running: background service '...' failed with ...` (or, when the library does not detect it, `ObjectDisposedException: ... 'IServiceProvider'`) | A `BackgroundService` of the app threw and .NET stopped the host; often it needs something the fixture lacks, such as a Kafka topic (`Unknown topic or partition`) | Read the service and its exception from the message (otherwise run with `--logger "console;verbosity=detailed"` and search for `BackgroundService failed`). Create what the service needs (list the topic in `Topics`) or remove it with `RemoveHostedService<T>()`. |
| The test project takes minutes while its tests take seconds | `IClassFixture<T>` on test classes or on the collection definition starts containers and the app for every test class | Share one fixture: `ICollectionFixture<T>` on the collection definition and `[Collection("...")]` on every test class. |
| The app ignores a message produced right after start; a delay after `StartAsync` "fixes" it | The app's Kafka consumer starts from `Latest` and was not assigned its partitions yet | Set `AutoOffsetReset` to `Earliest` for the app's consumers with `UseSetting`, or wait with `WaitForAssignmentAsync(groupId, topic, timeout)` when the app must keep `Latest`; don't add a delay. |
| `RpcException` with `Unimplemented` and "No stub matched the gRPC call '...'" from the app | The app called a gRPC method of a `WireMockHarness` that no stub answers, or the request did not satisfy the stubs' predicates | Read the rest of the message: it shows the request and tells whether the method has stubs. Add a stub or fix the predicate. |
| `ArgumentException: The gRPC method '...' takes '...' messages (X), not Y` when a stub is made | `WithGrpcMessage<TRequest>` names a message type the method does not take | Use the request type of the method named in `UsingGrpc`. |
| gRPC calls to a `WireMockHarness` fail with a protocol error such as `HTTP_1_1_REQUIRED`, or HTTP calls to it fail with 400 | gRPC needs HTTP/2 and the harness listens over HTTP/1.1, or the reverse | Set `UseHttp2 = true` on the harness that fakes gRPC, and use another harness for HTTP APIs. |
| The app cannot resolve or reach a `WireMockHarness` registered with `ServiceName` | The client calls `https://name`, another endpoint name, or the app does not use service discovery | Call `http://name` or `https+http://name`; set `EndpointName` for `http://_endpoint.name`; otherwise use `ConfigurationKey`. |
| The app ignores a setting the test added | The value came through `ConfigureAppConfiguration`, after `Program.cs` had read `builder.Configuration` | Use `.Configure(b => b.UseSetting("Key", "value"))`. |
| A test passes alone and fails with the whole project (or the reverse) | Tests share the app, its data and its mocks | Use unique ids, look for your own result, reset mocks and `WireMockHarness` before the test. |
| Containers fail to start or time out when the whole solution is tested | Many test projects start containers at once | Limit parallel projects: `dotnet test -m:4`. |
| Kafka test passes locally, flaky on CI | Reading "the next" message or a fixed short timeout | Wait for your key with a 10 s timeout; isolate topics per test. |
| `InvalidOperationException: PostgreSQL command failed: ...` | Template/database SQL failed (name in use, template has connections, PostgreSQL < 13) | Use unique names (≤ 63 bytes), let `CreateTemplateAsync` close connections, use PostgreSQL 13+. |
| "Duplicate mount point" when starting PostgreSQL | A volume is mounted at the data directory while the harness uses tmpfs | Set `Durable = true` on the harness. |
| A Redis config file's `save`/`appendonly` are ignored | The harness disables persistence by default | Set `Durable = true`. |
| Time-based test hangs | The app doesn't use `TimeProvider` from DI, or the clock was advanced before the code started waiting | Inject `TimeProvider`; advance after the request started waiting, or keep advancing until it completes. |
| Tests slow down or time out when several target frameworks run | Every target framework starts its own containers in parallel | Set `<TestTfmsInParallel>false</TestTfmsInParallel>` in the test project. |
| Containers left running after a crashed run | The test process was killed | Testcontainers' Ryuk removes them; otherwise `docker ps -a --filter label=org.testcontainers=true`. |
